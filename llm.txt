# nuxt-cms: LLM guide

Nuxt module embedding a CMS in the app's Nitro server. Content types are declared in code (`cms.config.ts`); DB schema, migrations, TypeScript types and a read-only GraphQL API are generated from it. Admin panel at `/cms`. This guide covers: defining the data schema, querying content from the app, and server hooks/webhooks.

## 1. Setup (nuxt.config.ts)

```ts
export default defineNuxtConfig({
   modules: ['@xleddyl/nuxt-cms'],
   cms: {
      i18n: { locales: ['en', 'it'], defaultLocale: 'en' }, // only needed if using translatable fields
   },
})
```

The whole `cms` key is optional. `database` defaults to `{ driver: 'sqlite', path: 'data/cms.db' }`; switch to `{ driver: 'postgres', url, poolMax }`, `{ driver: 'libsql', url, authToken }` (Turso/remote, or omit `url` for a local file) or `{ driver: 'd1', binding }` (Cloudflare Workers, binding defaults to `DB`); each driver only accepts its own keys (`path` on sqlite, `url`/`authToken` on postgres/libsql, `poolMax` on postgres, `binding` on d1), plus `migrateOnBoot` (default true) on all of them. Install only the client for the driver you use: `pg` for postgres, `@libsql/client` for libsql; sqlite and d1 need nothing extra. Admin credentials come from `NUXT_CMS_ADMIN_EMAIL` / `NUXT_CMS_ADMIN_PASSWORD` env vars. Admin branding: `admin: { title, subtitle, logo }` replaces `nuxt-cms` / `Content studio` (empty `subtitle` hides it) and the default mark in the sidebar, mobile bar and login page; `logo` is a URL or root-relative public path (`/logo.png`, rendered as `<img>`), a path to an `.svg` file in the project (root-relative or `~/`, `@/`, `~~/`, `@@/`, inlined at build with scripts, `foreignObject`, `on*` attributes and fixed width/height stripped, so `currentColor` follows the theme) or raw `<svg` markup; a missing file or a non-svg project file fails the build (put raster images in `public/`). Media is configured under `cms.media` or `NUXT_CMS_MEDIA_*` env vars: `storage: 's3'` (default) uses S3-compatible object storage (`endpoint`, `region`, `bucket`, `accessKeyId`, `secretAccessKey`, `publicBaseUrl`, `presignExpiry`, `maxFileSize` in bytes, default 10485760); in `'s3'` mode folders can be created and deleted from the panel (an empty folder is kept alive by a `<folder>/.keep` object); `storage: 'local'` makes the media library read-only (no uploads/edits/deletes, listing only), only accepts `publicBaseUrl` (required), serving files from it instead of a bucket. With a root-relative `publicBaseUrl` (e.g. `/images` → `public/images`) the library is read from that folder (media keys are the paths relative to it): live from disk with a 1s cache wherever the folder exists, otherwise from a manifest baked at build time (the serverless case, where `public/` is not on the function's filesystem, so new files show up after you commit and deploy). Nothing is ever written back: `cms_media` only stores alt texts and focal points, so dev and production can safely share one database. `storage: 'filesystem'` writes uploads to a directory on the server's disk (`dir`, default `data/media`, or `NUXT_CMS_MEDIA_DIR`), serves them under a root-relative `publicBaseUrl` (default `/media`) and accepts `maxFileSize`; it needs a persistent disk. The media detail drawer has a Download button for the original file in every storage mode, served by the admin route `GET /api/cms/admin/media/download?key=` (`attachment` disposition; `s3` redirects to a presigned GET, `filesystem` and `local` stream from disk, `local` without the folder on disk fetches `publicBaseUrl` and streams). The admin client checks the upload size against `NUXT_PUBLIC_CMS_MEDIA_MAX_FILE_SIZE`, so a runtime override must set it and `NUXT_CMS_MEDIA_MAX_FILE_SIZE` to the same value. Remote DB credentials (postgres/libsql) can be overridden at runtime with `NUXT_CMS_DATABASE_URL` / `NUXT_CMS_DATABASE_AUTH_TOKEN` (libsql only).

Other top-level keys: `enabled` (or `NUXT_CMS_ENABLED=0`) turns the CMS off while the module stays in `modules[]`: the query composables become stubs that return their empty default without a request, and the generated types stay. `graphql: { maxDepth }` (default 8) caps query depth. `preview: { path, component, banner }` sets the visual editor preview route (default `/cms/preview`), the default preview wrapper of content entries and the automatic banner of preview links (default true) (see Content). `admin.title`, `admin.subtitle` and `admin.logo` are build-time only (no env var). `site: { url }` is the absolute site URL (written to `runtimeConfig.public.siteUrl`, so `NUXT_PUBLIC_SITE_URL` overrides it; falls back to an existing `public.siteUrl`, then `site.url` of nuxt-site-config, then the request origin; must be http(s) without query, hash or credentials). `seo: { sitemap, robots }` (booleans) switch the `/sitemap.xml` and `/robots.txt` routes; unset, each is on unless `@nuxtjs/sitemap` / `@nuxtjs/robots` (or `nuxt-simple-*`) is installed or `public/sitemap.xml` / `public/robots.txt` exists, then it is off with a build warning (`true` keeps ours and warns). Unknown keys and wrong types fail the build. See section 4. `roles` declares the admin roles and their permissions (see Roles in section 2).

### Hooks and webhooks

After every committed admin write the module fires a Nitro runtime hook (typed via `NitroRuntimeHooks`), in the background: the handler does not wait, each callback is isolated (a throw is logged, never breaks the response), and the task goes to `event.waitUntil` for serverless. Admin settings (columns, layout, Settings → Site), block presets, redirects, preview links and user accounts fire nothing; direct DB writes fire nothing. The auto redirect of a slug change is part of the item save (same batch, same `update`/`publish` event).

```ts
// server/plugins/cms.ts
export default defineNitroPlugin((nitroApp) => {
   nitroApp.hooks.hook('cms:entry:change', (change, { event }) => {})
   nitroApp.hooks.hook('cms:media:change', (change, { event }) => {})
})
```

- `cms:entry:change`: `{ entry, kind, action, ids, path, status, item, user, at }`. `action`: `create` (new item, Duplicate, first save of a single), `update`, `publish` (status became published, also scheduling), `unpublish` (published to draft), `delete`, `import` (one event per import file, `ids` = every written id). `path` is set for page saves, `status` (`draft`/`published`) for entries with drafts, `item` is a copy of the saved row in admin API shape (private fields included; `null` on delete/import), `user` is `{ id, email, name, role }` (`id` null for the env super admin), `at` ISO UTC.
- `cms:media:change`: `{ action, keys, folder, from, user, at }`, `action`: `upload` (file registered), `update` (alt/focal point/folder), `move`, `delete`, `folder-create`, `folder-rename` (`from` = old name), `folder-delete`; `keys` never include folder markers.
- Types: `CmsEntryChange`, `CmsMediaChange`, `CmsEntryAction`, `CmsMediaAction`, `CmsHookUser` from `@xleddyl/nuxt-cms`.

Webhooks: `cms.webhooks: [{ name, url?, secret?, events?, timeout? }]` POSTs JSON for each change to every matching URL. `name` camelCase and unique; `url` http(s); `secret` 16+ chars; `events` `'entry'`, `'media'` or exact `'entry:<action>'` / `'media:<action>'` (default all); `timeout` ms (default 5000, max 30000). Validated at build (unknown keys too). URL and secret live in private runtime config and can be set at runtime with `NUXT_CMS_WEBHOOKS_<NAME>_URL` / `_SECRET` (`searchIndex` → `SEARCH_INDEX`); the webhook must still be declared with its `name`, one without a URL is skipped. Body: entry `{ event: 'entry:<action>', action, entry, kind, ids, path, status, at }`, media `{ event: 'media:<action>', action, keys, folder, from, at }` (no item, no user). Headers: `x-cms-event`, `x-cms-delivery` (uuid), and with a secret `x-cms-signature: t=<unix seconds>,v1=<hex HMAC-SHA256 of "<t>.<body>">`. Parallel, in the background, failures logged (name and host only), no retries. Receivers: `verifyCmsWebhook(request | rawBody, header | null, secret, toleranceSeconds = 300)` from `@xleddyl/nuxt-cms/webhooks` (Web Crypto, server-safe) returns the payload or `null`; it also exports `signCmsWebhook` and the payload types.

## 2. Schema definition (cms.config.ts, project root)

```ts
import { defineCmsConfig } from '#nuxt-cms'

export default defineCmsConfig({
   <entryKey>: {
      id: '<entryKey>',            // must equal the object key
      label: 'Human label',
      kind: 'collection' | 'single' | 'page' | 'content',
      titleField: 'name',          // collections: entry title in admin; text, slug, email, number, date, datetime or single select
      drafts: true,                // optional; adds draft/published status (GraphQL returns published only)
      fields: { <fieldKey>: <FieldInput>, ... },
      validate: (values, { locales, defaultLocale, path }) => [{ field?, message, level? }], // optional
   },
})
```

- `collection` = many rows (list + detail queries). `single` = one document (single query). `page` = one row per route of the app (see Pages below). `content` = one content type (news, blog) whose items have system fields and a body of blocks, with drafts and scheduling (see Content below).
- `id`, `createdAt` (collections only), `updatedAt` are automatic: never declare them as fields.

### Field types

Every field has `label: string` and optional `required?: boolean` and `private?: boolean`, plus `default`, `unique`, `immutable`, `min`/`max` where listed in the notes. Type-specific options:

| type       | extra options                                                                      | stored/queried as |
| ---------- | ---------------------------------------------------------------------------------- | ----------------- |
| `text`     | `textarea?: boolean`, `translatable?: boolean`, `min?`/`max?` (characters)          | String            |
| `richtext` | `translatable?: boolean`                                                            | String (HTML)     |
| `number`   | `integer?: boolean`, `min?`/`max?` (value)                                          | Float / Int       |
| `boolean`  | none                                                                               | Boolean           |
| `date`     | none                                                                               | String `yyyy-mm-dd` |
| `datetime` | none                                                                                | String, ISO 8601 UTC |
| `email`    | none                                                                               | String            |
| `slug`     | `from: '<fieldKey>'` (required; auto-generated from that text field, from its default-locale value when translatable) | String            |
| `select`   | `options: (string \| { value, label })[]` (required), `multiple?: boolean`         | String (enum) / `[String!]!` |
| `tags`     | `max?: number`, `suggestions?: boolean` (default true)                              | `[String!]!`      |
| `json`     | none                                                                               | JSON              |
| `media`    | `mediaType?: T \| T[]` where `T` is `'image' \| 'video' \| 'file'`, `accept?: string[]`, `translatable?: boolean`, `mobile?: boolean` | CmsMedia object   |
| `relation` | `to: '<entryKey>'` (required), `cardinality?: 'many-to-one' (default) \| 'one-to-one' \| 'many-to-many'`, `onDelete?: 'set null' \| 'cascade' \| 'restrict'` | related entry / list |
| `link`     | `to?: string[]`, `external?: boolean` (default true), `withLabel?: boolean`, `translatable?: boolean` | CmsLink object |
| `blocks`   | `blocks: Record<name, { label, fields, component?, icon?, description?, group?, tags?, layout?, validate? }>` (required), `min?`, `max?` | array of typed blocks |

Notes:
- `mediaType` restricts the picker and the upload accept list to one kind of file, or to several when given a list (`['image', 'video']` for a slot that takes a photo or a video, with a filter pill per type). Omitted, or `'file'` anywhere in it, means any file. `CmsMedia.type` tells the app what was actually picked (`image` / `video` / `file`), so one slot can render an `<img>` or a `<video>`; `width`/`height` are filled for PNG, JPEG, WebP and GIF images and for MP4, M4V, MOV, WebM and MKV videos.
- `mobile: true` on a top-level `media` field adds an optional `<field>Mobile` media field (same `mediaType`, `accept`, `tab`, `translatable`, label `<label> (mobile)`) right after it, for a small-screen variant. The frontend picks the breakpoint and falls back to the main media. Not allowed inside `blocks`; a declared `<field>Mobile` key is a config error.
- `link` points at an address or an internal target, stored as JSON: `{ url }` or `{ entry, id }` (page entry: `id` = page key like `about`; content entries with a `route`: item id), plus optional `label` (string, or `{ <locale>: text }` with `translatable`) and `newTab: true`. Options: `to` (internal entries allowed, each the page entry or a routed content entry; default all of them), `external: false` (no addresses), `withLabel` (asks for a link text), `translatable` (needs `withLabel` and i18n; only the text is per locale). Addresses: `http(s)://`, `mailto:`, `tel:`, root-relative `/path`, `#anchor`; `javascript:`, `data:`, other schemes, `//host`, spaces and control characters are refused (`linkUrlError`). Allowed in blocks; not filterable, sortable or titleField. `required` needs a target (a text alone is not enough); `showIf` works on a link field; as a showIf target only `empty` (no address and no target, the text does not count). `default`, `unique`, `immutable`, `min`, `max` are refused on links at build time. With `translatable`, the link text counts in the translation progress and the copy/clear actions. Duplicate copies the value. Admin: Internal/External switch, search across the allowed entries the role can read (title + path, draft/scheduled marked), URL input, link text, "Open in a new tab"; warns when the target is a draft, scheduled or deleted. Deleting a linked content item lists where it is linked first (`POST /api/cms/link-usage` `{ targets: [{ entry, id }] }`, needs `<entry>.read` for every target, reports only the entries the role can read); links keep their stored id, so slug changes need nothing. Admin search matches link texts and URLs. CSV: JSON text (a plain address reads as `{ url }`). Helpers in `#nuxt-cms`: `linkUrlError`, `linkUrlKind`, `isExternalLinkUrl`, `linkTargetNames`, `readLinkValue`, `linkHref`, `resolveCmsLink`, `linkReferences`, `linkLabelText`.
- `translatable` only works on `text`, `richtext`, `media` and `link` (with `withLabel`); requires `cms.i18n` locales. Stored per locale, resolved to a single value at query time via the `locale` argument (falls back to the default locale, then to any locale that has a value). Translatable `media` keeps the `CmsMedia` shape, so `cover { url alt }` is unchanged. Works inside `blocks` too, with the same query shape and no migration (the per-locale map lives in the block's JSON; blocks still holding a plain value are read as the default locale).
- Translation workflow (admin only, nothing in the API or schema): with more than one locale, every translatable value (`text`, `richtext`, `media`, the text of a translatable `link`, top level and inside blocks, on every entry kind incl. pages) filled in the default locale counts; a locale is `complete`, `partial` or `missing` by how many of those it also fills (empty rich text = empty, fields hidden by `showIf` skipped, `required` ignored). Language switches show a dot per non-default locale with a `3 of 5 values translated` tooltip (per field in forms, whole item in the visual editor); collection and content tables get a `Translations` column (badges per locale, on by default, hideable in the column settings, computed client-side from the list rows) and the page tree the same badges. The `...` menu of forms and of the visual editor has `Copy <from> into <to>` (fill empty values, or replace all after a confirm) and `Clear <locale>` (non-default only, confirm, values removed so they fall back); they edit the unsaved form, hidden for read-only users, who can still switch locales. Shared helpers in `src/runtime/shared/translations.ts`: `translationProgress`, `copyTranslations`, `clearTranslations`.
- `private: true` keeps a field out of the public GraphQL API: the column and the admin editor stay, but the field is absent from the entry type, the filters input, the sort enum, introspection and the generated `#cms-types`. Read those values server-side from the DB (`#cms-db` + `#cms-tables`), where they hold the raw column value (a media field holds the object key string). Use it when a value must only be served through your own authenticated route. Not allowed inside `blocks`: mark the whole `blocks` field private instead.
- `datetime` stores an instant as an ISO 8601 UTC string (`2026-05-01T08:30:00.000Z`). Input needs a time zone (`Z` or `+02:00`) and is stored in UTC; the admin picker uses the browser's time zone. Filters and sorts as a StringFilter.
- `tags` is a free list of strings stored as a JSON array (like multi-select), typed `string[]`, `[]` when empty. Values are trimmed, empty ones dropped and duplicates ignored case-insensitively (first spelling wins) by the admin and the API validation. `max` caps the count (integer >= 1, after dedup, `ValidationMessages.maxTags`; only while visible with `showIf`); `required` asks for one tag; `min` is refused. Admin: chips input, Enter or comma adds, Backspace on empty input removes the last, x removes one; `suggestions` (default true) suggests values already used in that field across the entry via `GET /api/cms/tags/<entry>/<field>` (admin session). Not allowed in blocks, not translatable, not a titleField; showIf tests it with `empty`/`has` only. CSV: JSON text or plain comma separated text.
- Block fields accept every type above (`link` included) except `slug`, `relation`, `blocks`, `tags`, multi-select, and `private`; `showIf` on a block field tests its siblings in the same block item. The admin edits a blocks field as a grid of tiles (preview, drag to reorder, click to open one block, `...` menu: Copy, Cut, Paste after, Duplicate, Save as preset; the Add picker lists the presets of the field too; Cmd/Ctrl+C/X/V on a focused tile, Cmd/Ctrl+V on the Add button appends); when every block of the field has a `component`, an "Open visual editor" button also edits it in the visual editor (block tree, canvas and the selected block form, no entry tabs; changes go back to the form). Any block item can carry `hidden: true` (block editor: Hide/Show): it dims the tile and, unless the block declares its own `hidden` field, drops the item from the public API.
- A block may name the site component that renders it: `component: 'SectionHero'` (or `'section-hero'`), plus `icon` (Heroicons outline) and `description` for the admin, `group` (non-empty string: the block picker lists blocks under group headings in config order, ungrouped ones last under Other) and `tags` (array of non-empty strings, extra search terms). Valid in every `blocks` field. The build fails when the component is not registered in Nuxt. Fields named `key`, `ref`, `class`, `style` are refused on a block with a component. `defineCmsBlocks({ ... })` from `#nuxt-cms` returns a block set unchanged (literal types kept) so several entries can share it. They may be `translatable`; the admin shows one locale switcher on the `blocks` field that drives every translatable sub-field.
- `tabs: [{ id, label }]` on an entry splits its admin form into horizontal tabs; `tab: '<id>'` on a field picks one. Admin-only: schema, column and query shape are unchanged. A field with no `tab` goes to the first tab; an entry with no `tabs` renders one plain form. An unknown tab id, a duplicate id or a tab with no label fails the build. Not allowed inside `blocks`. A failed save opens the tab holding the first invalid field.
- Login lockout: 5 failed logins from one IP, or for one email, return `429` for 5 minutes. Counters live in Nitro storage `cms:login-rate` (in-memory by default, so per instance). A successful login clears them.
- Media usage: each media tile and row shows how many entries use the file (or "unused"); deleting a used file or a folder shows the entries that use it first. The site share image counts as a use (`kind: 'site'`, "Site settings", links to `/cms/media?settings=site`; any admin URL with `?settings=<section>` opens that settings section). Moves and folder renames keep the media key, so references stay valid.
- Admin accounts: the env credentials (`NUXT_CMS_ADMIN_EMAIL`/`NUXT_CMS_ADMIN_PASSWORD`) sign in as the super admin (role `superadmin`, every permission, not stored in the DB, cannot be removed or locked out). Other accounts live in the `cms_users` table (scrypt hashes, `role` holds the role key) and are managed in Settings → Users. First sign-in offers an optional password change; Settings → Account changes name and password. `cms_users` is a reserved entry name.
- Roles (code-first, `nuxt.config` `cms.roles`): `{ editor: { label?, description?, can: ['news.*', 'events.read', 'events.update', '*.read', 'media.write'] } }`. Permission = `<scope>.<action>`: entry key with `read`, `create`, `update`, `delete`, `publish` (drafts only), `import`, `export` (collections/content) or `read`, `update` (singles/pages); `media.read|write|delete`; `users.manage`; `settings.manage` (Settings → Site and the column/layout overrides); `redirects.manage` (Settings → Redirects). `*` replaces one segment (`news.*`, `*.read`) or everything (`*`). Every action implies `read` on its scope. Built-in roles: `admin` (everything except `users.manage`, default for new and pre-existing accounts) and `superadmin`; both reserved. Validated at build: role key `^[a-z][a-zA-Z0-9_-]*$`, unknown keys, unknown entry/scope/action, `publish` without drafts, `users.*` when an entry is named `users` (ambiguous); warnings for a role that edits media/relation fields without `media.read` / `<target>.read` (also the declared `to` of link fields). Server: every admin endpoint calls `requireCmsPermission(event, perm)` (403 `Missing permission: <perm>`); search filters to readable entries (media hits need `media.read`); `GET settings` needs only a session; `GET`/`PUT /api/cms/site` need `settings.manage`; every redirects endpoint needs `redirects.manage` (the auto redirect of a save needs only the save's permissions); preview links: list needs `<entry>.read`, create and revoke need `<entry>.update` (the Share preview item shows only with it); block presets: use needs `<entry>.update`, Settings → Block presets `settings.manage`; the visual editor is read-only (`readonly` prop) under the same rule as forms (no `update`, or published without `publish`): inspector disabled, no canvas toolbar, `+`, drag or inline editing, tree not reorderable with a Copy-only menu, no picker, no Undo/Redo, data-changing keys and frame messages ignored; locale switch, selection and copy stay; the link picker and the preview only use entries the role can read. Publishing: with `update` but not `publish` a role saves drafts only; creating as published, publishing, unpublishing, scheduling and editing an already published item are 403 (import rows get the same errors). Import needs `import` + `create` (+ `update` for upsert). Users endpoints need `users.manage` plus the grant rule: assign a role only if you hold all its permissions, edit/delete an account only if you could assign its role; no self role change, no self delete, `superadmin` never assignable. A role removed from config grants nothing (panel shows it, users list flags it). The admin UI hides sidebar entries and actions with the same shared `can()` (from `src/runtime/shared/roles.ts`) and the session role, refreshed by the session fetch hook.
- Admin search: the sidebar search (⌘K / Ctrl K) matches config labels (entries, pages and paths, tabs, fields, blocks) and every stored text value (text, richtext without markup, slug, email, select, tags, json, block fields, page field rows, media alt texts) in all locales, private fields included. It is served by `GET /api/cms/search?q=` (admin session required, 2 to 200 characters, case-insensitive LIKE with `%` and `_` escaped, 10 rows per entry, 50 value hits). A hit opens the editor with `?field=<key>&locale=<code>&block=<index>`, which switches to the tab, locale and block of the field, scrolls to it and highlights it. Admin-only: nothing is added to the public API.
- `layout` on an entry arranges the admin form: `[row, ...]`, where a row is a field key or an array of up to 4 keys side by side, and `{ title, description?, collapsed?, rows }` is a titled section. Unnamed fields go at the end. Admin-only. Unknown or repeated keys and rows over 4 fields fail the build. A block takes `layout` too (same format, same build checks against the block fields): it arranges the block form in the tile grid modal and the visual editor inspector (rows stack under a 32rem wide form); not overridable in Settings. `list: { columns, filters }` (collections and content) sets the default table columns (`status` allowed with `drafts`) and the list filter buttons (single `select`, `boolean`, many-to-one/one-to-one `relation`, `status` with drafts; without `filters` the eligible fields that are visible columns, `[]` for none; other fields fail the build). `icon` (entry) sets the sidebar icon (Heroicons outline name). `description` and `placeholder` on a field add a help text and an input placeholder. Admins can override columns and layout in Settings; the override is stored in the `cms_settings` table and `settings`/`cms_settings` are reserved entry names.
- `showIf` hides a field in the admin until a condition on other fields holds. Condition: `{ field, <op>: value }` with `eq`/`neq`, `in`/`notIn` (non-empty list) on `select`, `boolean`, `text`, `number`, `date`, `datetime`, `email`, `slug`; `gt`/`gte`/`lt`/`lte` on `number`, `date` (`yyyy-mm-dd`), `datetime` (ISO, compared as instants); `empty: true|false` on every type except `boolean` (null, blank, `[]`, translatable with no locale, json `{}`, link without address or target); `has: '<value>'` on `tags` (case-insensitive), multi-select, many-to-many (an id). Several ops in one condition = AND. Groups `{ all: [...] }`, `{ any: [...] }`, `{ not: cond }`, nestable; a top-level array = all. A missing value fails `eq`/`in`/`has`/comparisons and passes `neq`/`notIn`. Translatable targets accept only `empty`. Admin-only display: schema, column and query shape unchanged; a hidden field keeps its stored value. On a conditional field `required` means "required while visible" and `min`/`max` apply only while visible, enforced by one shared evaluator in the admin form, the admin API (400) and the import, never by the DB (column nullable, GraphQL optional). Inside `blocks`, `showIf` targets sibling fields of the same block item. Validated at build: target exists (in the block for block fields), not itself, operator fits the target type, value type (boolean/number/valid date), select values in `options`, unknown keys, malformed groups. Not allowed on the `titleField`.
- Select labels: an option is a string or `{ value: 'members', label: 'Club members' }` (mixed allowed). The value is stored, validated, filtered, typed in `#cms-types` and used by `showIf`; the admin shows the label (input, table cells, select titleField, relation pickers, search, which also matches labels). Values unique and non-empty, labels non-empty, or the build fails. `CmsSelectValue<typeof field>` gives the value union of an `as const` field.
- `default`: initial value of a new item (create form, first save of a single, API create without the key, import row that creates an entry without the column; an explicit null stays null; Duplicate keeps the copied value). text/richtext string (translatable: default locale only), number (integer with `integer`, inside min/max), boolean, date `yyyy-mm-dd` or `'today'` (browser date in the admin, UTC date on the server), datetime ISO with zone or `'now'`, email, select option value (list with `multiple`), tags string list (<= max). Not on slug/json/media/relation/blocks, inside blocks or on pages. Validated at build.
- `unique: true` on `text`, `email`, `number` of collections/content: `.unique()` column (migration fails on existing duplicates), exact match, blank stored as null. The admin API pre-checks and answers 409 `{ data: { issues: [{ path: ['<field>'], message }] } }` (`ValidationMessages.unique`), shown under the field in the admin; Duplicate clears unique fields; import reports duplicates in the file or the table. Not on translatable fields, inside blocks, on pages or singles (slug is always unique and refuses the option).
- `immutable: true` on `text`, `number`, `boolean`, `date`, `datetime`, `email`, `slug`, `select`, `relation` (not many-to-many): once saved with a value, the admin shows it disabled and the admin API (and import upsert) refuses another value with 400 (`ValidationMessages.immutable`); a field saved empty can be filled once. Not translatable, not inside blocks, not on pages.
- `min`/`max`, one vocabulary sized by type: number value, text length in characters (each locale of a translatable text), blocks count, tags count (`max` only). Empty values skip them (use `required`). Admin form + admin API (400) with `ValidationMessages.minValue`/`maxValue`/`minLength`/`maxLength`; also valid on block fields; `minLength`/`maxLength` keys are refused at build. Admin API 400s carry `data.issues` (`path`, `message`) and the admin maps them to fields.
- Blocks count: `min` / `max` on a `blocks` field (integers, `min >= 0`, `max >= 1`, `min <= max`; `tags` takes `max` only). `max` always applies; `min` applies once the field has a block (add `required` to forbid empty). Checked by the admin form and the admin API (400) with `ValidationMessages.minBlocks` / `maxBlocks`; at `max` the admin disables add, duplicate and the visual editor `+`. With `showIf`, enforced only while visible.
- Validation hook: `validate(values, { locales, defaultLocale, path? })` on a collection, single, page or content entry, and `validate(item, { locales, defaultLocale, index })` on a block, returns `[{ field?, message, level?: 'error' | 'warning' }]` (or nothing). Errors block the save under the field (or at the form top without `field`; a block issue's `field` is a block field); warnings are shown in the admin and never block. `cms.config.ts` is imported (not serialized) by both the admin client and the server through `#cms-config`, so the same function runs before the request and again in the admin write endpoints (400). It must be synchronous and isomorphic (no DB, no server-only imports), runs on parsed values after type checks (empty fields are `null`, possibly while other fields are invalid). `defaultLocaleValue(value, defaultLocale)` from `#nuxt-cms` reads a translatable value in the default locale.
- Admin list tools (collections and content entries, not singles/pages): filters combine with AND with search, sort and pagination, live in the URL as `?filter.<field>=<value>` and are validated server-side by `GET /api/cms/admin/<entry>` (only offered fields, only option values / `true` / `false` / `draft` / `published` / an id up to 256 chars, else 400; boolean `false` also matches null). **Duplicate** (toolbar with one row selected, entry drawer footer, visual editor `...` menu, `/cms/<entry>/new?duplicate=<id>`) opens an unsaved copy: slug gets `-copy-<4 chars>`, one-to-one relations and `unique` fields cleared, a text titleField gets ` (copy)`, status draft, content `publishedAt` cleared, media copied as keys. **Export** `GET /api/cms/export/<entry>?format=json|csv` (+ list `search`, `sort`, `order`, `filter.*`) downloads `{ collection, exportedAt, total, items }` (items: id, fields, status, createdAt, updatedAt, admin API shape) or CSV (only without blocks and many-to-many; translatable fields as `<field>.<locale>` columns, json, multi-select and tags as JSON text). **Import** `POST /api/cms/import/<entry>?format=json|csv&mode=create|upsert&dryRun=true|false`, raw file as body, max 5 MB and 2000 rows: every row goes through the entry schema and `validate` hook, plus relation ids, library media keys, unique values (slug, one-to-one, `unique` fields), immutable values on updates, defaults on created rows, and ids (`create` refuses existing ids, `upsert` updates them); the dry run returns a per-row preview and the write needs a clean file and runs in one transaction (one batch on libSQL/D1). Admin session and same-origin rules as every admin endpoint.
- After changing the schema, restart dev (migrations are generated + applied on boot).
- Migrations live in `server/db/migrations/<driver>` and must be committed. They are inlined into the server bundle at build time (no filesystem access at runtime), which is what makes serverless hosts work; `migrateOnBoot: false` / `NUXT_CMS_MIGRATE_ON_BOOT=false` defers them to CI. D1 has no transactions and applies migrations on the first request instead of at boot.

### Pages

`kind: 'page'` holds the content of the pages of the app: one row per route, one admin section.

```ts
pages: {
   id: 'pages', label: 'Pages', kind: 'page',
   routes: 'auto',                 // default: one row per page file; or an explicit list of paths
   include: ['/extra'], exclude: ['/cms'],
   order: ['/', '/about'], labels: { '/': 'Home' },
   fields: { title: { label: 'Title', type: 'text', translatable: true } },   // every page
   overrides: { '/about': { intro: { label: 'Intro', type: 'text' } } },      // one path only
}
```

- `routes: 'auto'` reads the page files: dynamic routes are skipped, route groups leave the path.
- An override adds fields to one path; `null` removes a shared field from that path (`overrides: { '/': { gallery: null } }`). It may not redeclare a shared field, and two paths declaring the same field name must use the same type.
- `path` is reserved and unique; the row id comes from the path (`/a-b/c` gives `aBC`, `/` gives `home`).
- One page entry per config; no `titleField`, no `drafts`, no delete from the admin.
- Storage: the page table holds `id`, `path`, `updated_at` and the fields listed in `columns: ['metaTitle', ...]` (optional, each must exist on every page); every other value is a row of `<entry>_fields` (`page_id`, `key`, `position`, `value`) or `<entry>_media` (`page_id`, `key`, `position`, `media_key`). Block values are rows keyed `<field>.<subfield>` per `position`, plus `<field>._type`. Relations and slugs must be in `columns`; many-to-many is not supported. GraphQL, types, queries and admin see one flat object per page. Upgrading from 0.1.56 or earlier is breaking: the generated migration drops the old page columns, so add a hand-written data copy between its CREATE TABLEs and DROPs (see docs/schema.md).
- Saving a page rejects (400) media keys that are not in the media library.
- In the admin the pages are a tree that follows the routes, and the editor title is a breadcrumb.
- Queries: `<entry>(locale)` for the list, `<entry>ByPath(path, locale)` for one page.
- A script that loads `cms.config.ts` by itself gets no routes: fill them with `resolveCmsPages(config, { root?, pagesDir? })` from `@xleddyl/nuxt-cms/seed`.

### Content

`kind: 'content'` is one content type (news, blog, ...); declare one entry per type.

```ts
const sections = defineCmsBlocks({ text: { label: 'Text', component: 'SectionText', fields: { ... } } })

news: {
   id: 'news', label: 'News', kind: 'content', icon: 'newspaper',
   blocks: sections,                                                        // required: body blocks
   fields: { category: { label: 'Category', type: 'relation', to: 'categories' } }, // optional extras
   labels: { excerpt: 'Summary' },                                          // optional system labels
   tabs, layout, list,                                                      // as on collections
   preview: { component: 'NewsArticle' },                                   // optional preview wrapper
   route: '/news/[slug]',                                                   // optional public path pattern
}
```

- System fields, injected (declaring one is a config error): `title` (text, translatable, required, the titleField), `slug` (unique, required, generated from the title in the default locale), `publishedAt` (datetime), `excerpt` (textarea, translatable), `cover` (media image), `body` (blocks from `blocks`), `seoTitle`, `seoDescription` (translatable), `seoImage` (media image), `seoNoindex` (boolean: `useCmsSeo` sets `robots: noindex` and the sitemap skips the item; the API still returns it). Text fields are translatable only when `cms.i18n.locales` is set.
- Always has draft/published `status`, `createdAt`, `updatedAt`. `titleField`, `drafts`, `columns`, `routes`, `overrides` and a custom `table` are config errors. Default list columns: title, status, publishedAt.
- Public API: only `status = published` and `publishedAt <= now`. Drafts and scheduled items (published with a future date) are invisible to list, count, byId, bySlug and relations (except the item of a valid preview link, see Preview links below). Publishing with an empty `publishedAt` sets it to now.
- Relations may target a content entry (`to: 'news'`).
- Admin: sidebar group Content; list badge "Scheduled" for future items; items open in the visual editor (`/cms/<entry>/new`, `/cms/<entry>/<id>`): top bar (back, title, status, locale switch, Undo/Redo, Schedule, Save, Publish/Unpublish, `...` menu with translation actions, Share preview, Duplicate, Delete) and three panels. - `route` (content entries only) is the full path the site serves for an item: `'/news/[slug]'`, or with `cms.i18n` a map naming every locale, `{ en: '/blog/[slug]', it: '/it/blog/[slug]' }` (no automatic locale prefix: write what your router serves; a single string is the path in every locale). Isomorphic helpers in `#nuxt-cms`: `contentItemPath(entry, item, locale)`, `contentItemPaths(entry, item, locales)`, `matchContentPath(config, path, locale)` (candidate `{ entry, pattern, params }`, most specific first), `matchContentPattern`, `contentPathParamsMatch`, `buildContentPath`; server: `findContentByPath(name, path, locale, { includeDrafts? })`.
- `preview: { component }` (content entries only; `cms.preview.component` in nuxt.config is the default for all) names a site component that wraps the body in the visual editor. It gets `item` (public fields in the active locale, media as `CmsMedia`, relations as ids, unsaved values) and `locale`, and renders the body in its default slot. Reuse it on the site page with `<CmsBlocks>` in the slot.
- Preview links: visual editor `...` menu **Share preview** (saved items of routed content entries) creates `<item path in locale>?cms-preview=<token>` (never published items use the path of the current slug; date placeholders need `publishedAt`) with an expiry of `1h`, `1d` (default), `7d` or `30d`, copies it, and lists the active links of the item with Revoke. It shows the saved version (later saves included, unsaved never; the dialog offers Save and create link). Admin API (same-origin, `requirePreviewLinkAccess(event, entry, 'read' | 'update')`: list needs `<entry>.read`, create/revoke `<entry>.update`): `GET`/`POST /api/cms/preview-links/<entry>/<id>` (`{ duration, locale? }` returns `{ link, url }`), `DELETE /api/cms/preview-links/<entry>/<id>/<linkId>` (revoke). Site: every query composable and `$cmsQuery` (when the Nuxt app is available) forward `?cms-preview=` of the current route as the `x-cms-preview` header (SSR too); with a valid, unexpired, unrevoked token `<entry>ByPath`, `<entry>BySlug`, `<entry>ById` (so `useCmsRoute`, `useCmsContent`) also return that one item when draft or scheduled; lists, counts, relations and other items stay published only; an invalid token behaves as none (404 for drafts). Preview requests skip in-flight dedupe, are batched per token, get `useAsyncData` keys ending in `:cms-preview`; responses with the query or header get `Cache-Control: private, no-store`, `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: same-origin` (bypass any CDN/ISR cache for `cms-preview`). A client banner "Preview" with the expiry is rendered automatically (`cms.preview.banner: false` turns it off; must be a boolean); `useCmsPreviewMode()` returns a computed `{ entry, id, expiresAt } | null` (from `GET /api/cms/preview` with the header). Helpers in `#nuxt-cms`: `PREVIEW_QUERY_PARAM`, `PREVIEW_HEADER`, `PREVIEW_LINK_DURATIONS`, `isPreviewToken`, `previewTokenFrom`, `previewLinkUrl`, `previewLinkExpiry`, `isPreviewLinkActive`, `previewGrantAllows`; server: `findPreviewGrant(token)`, `hashPreviewToken`.
- Preview page: `cms.preview.path` (default `/cms/preview`, one lowercase segment under `/cms`, not `login`, `logout`, `media` or an entry name). Rendered in the site's default layout, admin session required, `X-Robots-Tag: noindex, nofollow`, `X-Frame-Options: SAMEORIGIN`. It never reads the public API: the admin posts the unsaved data via `postMessage` (origin and source checked both ways; the page asks again after a reload). Block components need a single root element (the editor finds blocks by `data-cms-block`). Keep `/cms/**` out of sitemaps.

## 3. Querying content

Public read-only GraphQL endpoint at `POST /api/cms/graphql`. Auto-imported composables. `useCms` and `$cmsQuery` are typed end-to-end from the query string, with no codegen step:

```ts
// one entry, query and types generated from cms.config.ts
const { data } = await useCmsSingle('homepage', { locale })
const { data } = await useCmsCollection('events', { filters, sort, limit, offset, locale })
const { data } = await useCmsPage('/about', { locale })
const { data } = await useCmsContents('news', { filters, sort, limit, offset, locale }) // publishedAt desc by default
const { data } = await useCmsContent('news', slug, { locale })                        // null when unknown, draft or scheduled
const { data } = await useCmsRoute(route.path, { locale })   // { entry, item } of the routed content item at that path, or null
const { data } = await useCmsSite({ locale })                // site settings (CmsSite) or null
const preview = useCmsPreviewMode()                           // { entry, id, expiresAt } on a preview link, else null
useCmsSeo(item, { locale })                                   // head tags of the page, see section 4

// reactive, SSR-friendly (wraps useAsyncData): use in components/pages
const { data, error, refresh } = useCms(`{ ... }`, variables?, options?)

// plain promise: use in event handlers or server-side logic
const result = await $cmsQuery(`{ ... }`, variables?)
```

`useCmsSingle` / `useCmsCollection` / `useCmsPage` need no query string. `useCmsPage` takes a typed path of the `page` entry and returns the fields of that path (shared plus its own). They select every public field of the
entry plus `id`, `updatedAt` and `createdAt`: media with all its keys, blocks with one inline
fragment per block type, relations one level deep (without the relations of the related entry).
`data` is `null` for a single and `[]` for a collection while loading and after a failure.
`sort.field` accepts only that entry's field names. Use `useCms` for a count, for a relation two
levels deep, for several entries in one request, or for a narrower selection.

`useCms` takes a third argument that forwards options to `useAsyncData`: `key` (replaces the
generated cache key), `default` (the value `data` holds before the query resolves and after it
fails), plus `server`, `lazy`, `immediate`, `deep`, `dedupe` and `watch`. The entry helpers take the
same options next to their own.

Queries started in the same tick (by any of these composables or `$cmsQuery`) go out as one batched HTTP request, and identical queries in flight share one request; keys and results are unchanged.

### Generated queries

For each **collection** `events` (GraphQL type name = PascalCase of key):

```graphql
events(filters: EventsFilters, sort: [EventsSort!], limit: Int, offset: Int, locale: String): [Events!]!
eventsById(id: ID!, locale: String): Events
eventsCount(filters: EventsFilters): Int!
```

For each **single** `homepage`:

```graphql
homepage(locale: String): Homepage
```

For each **content** entry `news`: the collection queries plus `newsBySlug(slug: String!, locale: String): News`. Without `sort` the list is ordered by `publishedAt` desc. With a `route`: also `newsByPath(path: String!, locale: String): News`, and `News.path` / `News.paths`.

`useCmsRoute(path, { locale })` sends one request with `<entry>ByPath` for every routed content entry and returns `{ entry, item }` (`CmsContentRouteMatch`, a union on `entry`, items as in `useCmsContent`) or `null`; for one catch-all page serving every content type. It matches `path` against the pattern of `locale` (default locale when omitted), ignores query, hash and trailing slash, and prefers the pattern with more fixed segments.

### Filters, sort, pagination

Filterable: `id`, `createdAt`, `updatedAt`, and every field except `json`, `blocks`, `translatable` fields and `private` fields (single relations filter by the related id as a StringFilter). Multi-value fields (multi-select, `tags`, `many-to-many` relations) filter with `StringListFilter` and are not sortable.

Filter operators. String: `eq neq gt gte lt lte like in isNull`; Int/Float: `eq neq gt gte lt lte in isNull`; Boolean: `eq neq isNull`; StringListFilter: `hasAny: [String!]` (holds at least one), `hasAll: [String!]` (holds every one), `isEmpty: Boolean` (empty or null / at least one item). Values match exactly (case-sensitive); on many-to-many they are related ids (join table, drafts included). Empty `hasAny`/`hasAll` list is an error. Everything is ANDed. Example: `guides(filters: { spots: { hasAny: ["Po"] }, regions: { isEmpty: false } })`; the same object goes in `useCmsCollection(name, { filters })`.

Sort: `[{ field: <fieldName>, direction: asc | desc }]` (direction defaults to `asc`).

### Media, links & blocks in queries

`link` fields resolve to `CmsLink { href label newTab external entry id }` (always nullable, `CmsLink` in `#cms-types`, selected by the generated queries). `href`: the URL, the page path, or the content item path in the requested locale; `null` when the target is deleted, a draft or scheduled (also through preview links). `label` is localized with fallback, `external` is true for `http(s):`/`mailto:`/`tel:` addresses, `entry`/`id` are null for addresses. Internal targets are batched per request (one query per entry). Render with `<CmsLink :link="item.cta" />` (auto-imported): a `<NuxtLink>` with `target="_blank" rel="noopener noreferrer"` for `newTab`, `label` (or href) as default slot content, nothing when `href` is null. In the visual editor preview links resolve the same way (unsaved values included).

`media` fields resolve to: `{ key url type alt folder mime size width height focalX focalY }`, where `type` is the
enum `CmsMediaType` (`image` / `video` / `file`) and `url` is `publicBaseUrl` + "/" + `key`, `null`
only when `publicBaseUrl` is not configured. `focalX` / `focalY` (nullable floats, 0 to 1 from the
left/top edge, both null = not set, which means center) are the focal point an editor marks by
clicking or dragging on the image in the media detail drawer (Reset clears it; arrow keys nudge it;
needs `media.write`; saved with `PUT /api/cms/admin/media` `{ key, focalX, focalY }`, both or
neither, fires `cms:media:change` `update`). Stored in `cms_media` (`focal_x`, `focal_y`) in every
storage mode, `local` included (like alt texts).

Images: `<CmsImage :media="item.cover" sizes="sm:100vw md:50vw" />` (auto-registered) renders an image
`CmsMedia` (nothing for video/file or a null `url`) with `alt` (the `alt` prop overrides the media
alt; empty string when none), `width`/`height` from the media (pass one and the other follows the
aspect ratio, or both), `loading="lazy"` and `decoding="async"` by default, and the focal point as
`object-position` on the `<img>` (pair with `object-fit: cover`). With `@nuxt/image` installed it
renders `<NuxtImg>` (`picture` prop: `<NuxtPicture>`, the focal point goes to its `<img>`) and every
other attribute (`sizes`, `densities`, `format`, `quality`, `fit`, `preset`, `placeholder`, ...)
passes through; `provider` and `modifiers` are forwarded, and with the `imgix` provider (the
`provider` prop or `image.provider`) the focal point is also sent as `crop: 'focalpoint'` +
`fp-x`/`fp-y`. Other providers get `object-position` only. Without `@nuxt/image` it renders a plain
`<img>` (no variants). `storage: 'filesystem'` files are not in `public/`, so with the default
`ipx` provider and no `provider` prop it also renders a plain `<img>`; `'s3'` with `ipx` needs the
CDN host in `image.domains`. Helpers from `#nuxt-cms`: `focalObjectPosition(media)`,
`focalPointOf(media)`, `cmsImageSize(media, { width, height })`.

Each `blocks` field has an interface `<Entry><Field>Block` implemented by all its block types. The
interface holds `type` plus every field that all blocks of the field declare, so a field with one
block type needs no inline fragment. Use an inline fragment for the fields of one block type; block
type names are `<Entry><Field><Block>`:

```graphql
gallery { type hidden photo { url alt } }
body { type ... on EventsBodyHero { heading image { url alt } } }
```

Block fields are always nullable in GraphQL and in `#cms-types` (`string | null`), `required` included: inside blocks `required` is an admin and save-time rule only, because stored items can predate the field. `type` and `__typename` stay non-null.

Rendering: `<CmsBlocks :blocks="item.body" />` renders each block with its `component`, the block fields as props (no `type`/`__typename`), skipping hidden blocks and blocks without a component (dev warning). It finds the component by `__typename` (selected by the generated queries); for data without it pass `entry="news" field="body"` (`field` defaults to `body`). `annotate` adds `data-cms-block` (index) and `data-cms-block-type` to each root element. Mark the element that shows a field with `<CmsField name="heading" as="h2">{{ heading }}</CmsField>` (`as` defaults to `span`, attributes pass through) or `v-cms-field="'heading'"` (both auto-registered): they add `data-cms-field` only inside the editor preview, nothing on the public site. Inside a block the name is a field of that block (nearest `data-cms-block` ancestor); outside every block (preview wrapper) it is a field of the item (`title`, `excerpt`, extra fields); unknown names and private fields are ignored. For in-place editing of a `text` field, render the value as the element's only content (`{{ heading }}`), keep the element when empty if it should stay clickable, and use `white-space: pre-line` for a textarea. Components come from a build-time map (`#cms-blocks`) of lazy imports from `#components`. Type a block component with the generated interface: `defineProps<NewsBodyTextProps>()` from `#cms-types` (name `<Entry><Field><Block>Props`); `CmsBlockProps<'news', 'body', 'text'>` is the same type for use outside `defineProps` (Vue's compiler cannot resolve the generic there).

### Example

```ts
const { data } = useCms(`query ($cat: String!) {
   homepage(locale: "it") { heroTitle }
   events(
      filters: { date: { gte: "2026-01-01" }, category: { eq: $cat } }
      sort: [{ field: date, direction: desc }]
      limit: 10
      offset: 0
   ) {
      id title date slug
      poster { url alt }
      category { id name }
      tags { id name }
   }
   eventsCount
}`, { cat: 'some-category-id' })
```

Behavior:
- Introspection is disabled outside development (`Introspection is disabled`). A query selects at most 500 fields (fixed) and nests at most `graphql.maxDepth` levels.
- `createdAt` / `updatedAt` are ISO 8601 UTC strings on every driver.
- Entries with `drafts: true` only return `published` rows (drafts are invisible to the API). Content entries also hide published items whose `publishedAt` is in the future.
- Fields with `private: true` are not in the schema at all: they cannot be selected, filtered or sorted on.
- `locale` omitted → default locale; unknown locale → error; missing translation → falls back to default locale.
- Relations resolve nested entries (localized with the parent's locale); a required many-to-one pointing to a drafted entry can still be null.

## 4. SEO

- Site settings: admin **Settings → Site** (roles with `settings.manage`): site name and default description (per locale with i18n), title template (`%s` page title, `%siteName` site name, default `%s | %siteName`, must contain `%s`), share image (media key, checked against the library), `hidden` switch. Stored as the `cms_settings` row `cms:site` (no migration, no config entry). Admin API `GET`/`PUT /api/cms/site` (`settings.manage`); saving fires no hook. Public GraphQL: `cmsSite(locale: String): CmsSite!` with `{ name titleTemplate description image: CmsMedia hidden }` (localized, fallback to the default locale); `CmsSite` is a reserved type name. `useCmsSite({ locale, ...asyncDataOptions })` reads it.
- `useCmsSeo(item?, options?)` (auto-imported; item is a value, ref or getter) sets with `useHead`/`useSeoMeta`: `<title>` through the template (disables the app `titleTemplate` for that page; no title or a title equal to the site name gives the site name), `description`, canonical + `og:url` (site URL + `item.path`, else the route path), `og:title`/`twitter:title` (title without template), `og:site_name`, `og:type` (`article` when `publishedAt`, else `website`), `og:image` (+ width, height, type, alt) and `twitter:image`/`twitter:card` (absolute URLs, images only, video covers skipped), `article:published_time`/`modified_time`, `robots` (`noindex, nofollow` when the site is hidden, `noindex` for `seoNoindex`), hreflang `<link rel="alternate">` from `item.paths` plus `x-default` (default locale path), none when all locales share one path. Field convention for content and page rows: title `seoTitle` > `title`; description `seoDescription` > `excerpt` > `description` (HTML stripped) > site default; image `seoImage` > `cover` > site image; `seoNoindex`; `path`; `paths`. Name page fields `seoTitle`, `seoDescription`, `seoImage`, `seoNoindex`. Options (values, refs or getters) override: `title`, `description`, `image` (URL, media or `null`), `path`, `alternates` (`{ locale, path }[]`), `noindex`, `type`, `titleTemplate` (`false` = raw title), plus `locale` (static). Returns `{ site, meta }` (`meta`: computed `CmsSeoMeta` `{ title, pageTitle, description, canonical, image, robots, alternates, type, siteName, publishedTime, modifiedTime }`). Pure helpers in `#nuxt-cms`: `resolveSeoMeta(item, site, { siteUrl, path, defaultLocale }, overrides)`, `applyTitleTemplate`, `seoAlternates(paths, siteUrl, defaultLocale)`, `absoluteUrl(siteUrl, path)`, `normalizeSiteUrl`. Server utils: `readSiteSettings()`, `resolveSiteUrl(event)`. Works with the CMS disabled (item only).
- `/sitemap.xml`: routes of the page entry (`lastmod` from the row; dynamic paths, `/cms/**` and rows with a truthy `seoNoindex` skipped) and every published, non-scheduled, non-`seoNoindex` item of routed content entries (`lastmod` = `updatedAt`), one `<url>` per distinct path with `xhtml:link` hreflang alternates + `x-default` when the locales have different paths. Empty when the site is hidden. Read in batches of 1000, streamed; above 50,000 URLs it is a sitemap index of `/sitemap.xml?part=N` (each part one source). `Cache-Control: public, max-age=600, s-maxage=600`.
- `/robots.txt`: `User-agent: *`, `Disallow: /cms/`, `Sitemap: <site>/sitemap.xml` (when a sitemap is served and the site is not hidden). A hidden site keeps robots.txt open (crawlers must fetch pages to see noindex), gets an empty sitemap, the `robots` meta tag from `useCmsSeo` and `X-Robots-Tag: noindex, nofollow` on every response except `/cms/**`, `/_nuxt/` and `/__nuxt*` (server middleware `hidden-site`, settings cached in memory for 30 s and cleared on save).
- Redirects: admin **Settings → Redirects** (list, search, add, edit, delete, CSV/JSON import and export; roles with `redirects.manage`, checked by `requireCmsPermission(event, 'redirects.manage')`; manual writes fire no hook). Built-in table `cms_redirects` (`id`, `from` (`from_path`, unique), `to` (`to_path`), `status` 301|302|307|308 (default 301), `keepQuery` (default true), `source` `'manual'|'auto'`, `createdAt`, `updatedAt`), created by the generated migrations; `cms_redirects` is a reserved entry/table name. `from`: a path starting with `/`, no host/query/hash, not under `/cms`, `/api`, `/_nuxt`, unique after normalization (`normalizeRedirectPath`: trailing and repeated slashes, query and hash dropped, percent-encoding canonical; case-sensitive). `to`: a path or an absolute http(s) URL (no credentials). Self redirects and loops through internal targets are refused (`findRedirectLoop`). Admin API (`redirects.manage`, same-origin): `GET`/`POST /api/cms/redirects`, `PUT`/`DELETE /api/cms/redirects/:id`, `POST /api/cms/redirects/import` `{ redirects: [{ from, to, status?, keepQuery? }] }` (max 5000, all-or-nothing, a row with a stored `from` replaces it). Not in the public GraphQL API. Automatic: saving a live (published, `publishedAt` past) routed content item whose path changes (slug, or `publishedAt` with date placeholders) writes an `auto` 301 from each old locale path to the new one in the same batch, re-points redirects whose target was the old path (chains collapse to the newest path) and deletes redirects whose `from` is now a live path of the item (moving back never loops). Drafts, scheduling, unpublishing, deleting, imports and route pattern changes make none. Runtime: server middleware `redirects` for `GET`/`HEAD` outside `/cms`, `/api`, `/_nuxt`, `/__nuxt*`: looks up the normalized path in an in-memory map (30 s TTL, cleared on writes on the same instance), skips it when a static route of the page entry or a live routed content item answers there (a page wins over a redirect), else `sendRedirect` with the stored status, appending the request query after the target's own when `keepQuery`. Pure helpers in `#nuxt-cms`: `normalizeRedirectPath`, `redirectFromErrors`, `redirectToErrors`, `redirectErrors`, `redirectLocation`, `planRedirectMoves`, `contentItemMoves`, `redirectRowsFromTable`, `redirectsToTable`.
